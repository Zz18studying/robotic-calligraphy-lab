# 机器人毛笔书写的字形规划与视觉反馈：截至目前的研究报告

**项目背景**：原申报项目为“大模型驱动具身智能的机器人绘画风格学习与个性化表达研究”。现阶段选择汉字毛笔书写作为可验证的子任务：输入一个字，得到目标笔画与动作，在合成毛笔环境中书写，并利用已写墨迹修正后续动作。

**报告范围**：本报告只陈述当前仓库中已经实现、可运行和可检查的内容。原申报书中的大模型生成、个性化风格学习、VLA 运动规划、ROS 2 接入和真实机械臂视觉/力控仍是后续目标。

## 1. 研究问题与阶段目标

最终设想是“用户给出要写的字和风格，系统自动规划笔顺、笔锋与动态动作，由机械臂完成毛笔书写，并根据相机图像继续修正”。中期阶段先验证其中一条最小闭环：

```text
汉字 → 有序笔画轮廓与中线 → 虚拟试笔标定 → (x,y,下压,速度)动作
     → 合成毛笔落墨 → 写前/写后图像差分 → 调整下一笔
```

核心问题有三个：静态字形怎样转为有顺序的动作；毛笔笔触宽度怎样和控制量建立关系；可见墨迹能否为后续笔画提供有效反馈。

## 2. 数据及其边界

使用本地 `data/graphics.txt`，共 **9,574** 条汉字记录。根据 [Make Me a Hanzi 官方数据说明](https://github.com/skishore/makemeahanzi/blob/master/README.md)，`strokes` 是按笔顺排列的 SVG 笔画轮廓，`medians` 是对应的中心线。程序将它们转换为统一纸面坐标，并分别生成每笔目标掩膜和整字目标图。`dictionary.txt` 保存原始字典信息，但当前算法不使用其释义。

该数据集没有真实毛笔书写时的法向力、笔尖高度、速度、倾角、含墨量、纸张状态或同步视频。因而中心线可提供初始方向和顺序，轮廓可提供最终形状，但**不能从静态字图唯一恢复真实力度与速度**。目前的下压和速度均为归一化虚拟控制指令。

## 3. 已实现的方法

### 3.1 虚拟毛笔与试笔标定

合成环境在轨迹采样点放置沿运动方向拉长的笔触，并逐点叠加墨迹。环境包含接触响应滞后、笔尖拖曳、下压和速度影响、纸面扩散、位置偏差、轻微纸面形变、墨量随笔画递减。这些因素让同一动作与理想目标出现可观察的差异，但参数尚未由真实毛笔实验测定。

程序以 5 档下压 `d` × 3 档相对速度 `v` 写 15 条虚拟直线，测量二值墨迹面积除以轨迹长度得到笔触宽度 `w`，以最小二乘拟合：

```text
ŵ(d,v) = a + b·d + c/v + e·d/v
L_cal = mean((ŵ - w_observed)²)
```

由目标宽度和选择的速度反求下压指令，并限制在允许范围内。256 像素“永”字演示所用试笔模型 RMSE 为 **0.477 像素**。标定数据和拟合系数在演示目录的 `calibration.csv`、`calibration.json`。这是**线性回归式系统辨识**，不是深度学习，也没有租服务器或训练大模型。

### 3.2 从目标轮廓规划动作

对每笔中心线求切线与法线，再沿法线搜索目标轮廓两侧边界。两侧距离之和估计所需笔触宽度，左右不对称量形成轨迹偏移。通过标定模型反求逐点下压指令；速度目前按局部曲率、起笔和收笔规则设置。输出的 `planned_actions.json` 每个采样点包含 `x`、`y`、`depth_command`、`speed_command`。

这比“只沿中心线固定压力”多考虑了目标笔画的粗细和不对称性。不过侧锋、顿笔、钩捺、枯笔等复杂笔法不能由单一截面宽度完整表达。速度仍有规则成分，不能称为从数据学习到的真实速度。

### 3.3 逐笔视觉反馈

每笔结束后，将写前和写后的**累计纸面图像**做差，得到新出现的可见墨迹，再与该笔尚未被先前笔画覆盖的目标区域比较。控制器用新增墨迹质心误差更新后续路径偏移，用面积及越界误差更新后续下压倍率，并限制修正幅度。控制器不读取虚拟毛笔内部的真实位置偏差等隐藏参数。

反馈频率是**每完成一笔一次**，尚未实现笔画内部的实时图像闭环。相机配准、光照、遮挡和延迟目前也没有进入仿真。

## 4. 评价函数与对照设计

在相同汉字、相同虚拟环境下比较三组方法：

| 方法 | 轨迹和控制量 | 反馈 |
|---|---|---|
| 固定参数 | 数据集中心线；固定下压与速度 | 无 |
| 轮廓标定开环 | 轮廓修正轨迹，标定模型反求下压 | 无 |
| 逐笔视觉闭环 | 与开环使用同一初始规划 | 每笔后修正下一笔 |

整字墨迹用 `IoU = 交集/并集` 和 `L_ink = (漏写像素 + 2×越界像素)/目标墨迹像素` 评价。越界权重 2 是当前实验的设计选择，因为已落下的墨迹不能擦除。逐笔反馈内部还使用质心与面积偏差。这里的 `L_cal` 用于回归拟合，`L_ink` 用于结果评价；当前没有一个反向传播训练的端到端网络损失。

## 5. 实验结果

### 5.1 原型开发组

192×192 分辨率，7 字（永、木、人、大、水、山、十）× 3 种合成环境（标准、墨量衰减、较大位置偏差），共 21 组：

| 方法 | 平均 IoU ↑ | 平均加权墨迹误差 ↓ |
|---|---:|---:|
| 固定参数 | 0.7299 | 0.5166 |
| 轮廓标定开环 | 0.7606 | 0.3699 |
| 逐笔视觉闭环 | 0.7953 | 0.2929 |

闭环相对开环的平均加权误差下降约 **20.8%**，21 组均下降。逐组数值见 [开发组实验结果](../outputs/closed_loop_sim/实验结果.md)。这些字参与过参数调整，因此不能把这一组称为独立测试。

### 5.2 补充汉字组

保持反馈增益不变，另用中、天、春、秋、月 5 字，在同样三种合成环境下运行 15 组。开环平均 IoU/误差为 **0.7251 / 0.3949**，闭环为 **0.7948 / 0.2703**；15 组加权误差均下降。见 [补充组实验结果](../outputs/heldout_sim/实验结果.md)。这说明方法在同一笔刷模型族的额外字符上仍有效，**不代表跨真实毛笔、纸张和书体的泛化**。

### 5.3 单字可视化

256×256 的“永”字 [对照图](../outputs/ppt_demo/永_standard/comparison.png) 对应固定、开环、闭环 IoU **0.637 / 0.787 / 0.814**；加权误差 **0.408 / 0.322 / 0.266**。分辨率与批量实验不同，不应混用数值。[逐笔动画](../outputs/ppt_demo/永_standard/writing.gif)展示虚拟毛笔的动态落墨，[逐笔误差图目录](../outputs/ppt_demo/永_standard/strokes/)可检查每笔漏写与越界。

## 6. 阶段结论与项目目标差距

当前已完成**字形读取、虚拟试笔拟合、轮廓引导动作规划、合成墨迹生成、逐笔图像反馈与对照评价**。它证明了一个可解释的算法链路能够运行，并在本合成环境中比固定参数和开环方法得到更低的墨迹误差。

以下内容尚未实现：真实毛笔和相机数据标定；机械臂逆运动学、坐标变换与力控；笔画内部实时反馈；用户风格输入、个性化字形生成与大模型/VLA 控制。因此现阶段成果应称为“毛笔书写动作规划与逐笔视觉反馈仿真原型”，不能称为“端到端 AI 机械臂自动书法系统”。

## 7. 下一阶段计划与可检验节点

1. **真实试笔**：固定笔、墨、纸，采集末端位置/速度、法向力或笔尖高度、同步纸面图像。每档条件重复多次，记录均值和方差。
2. **重建笔刷映射**：将真实试笔宽度与浓淡代入标定流程；若线性宽度模型失效，加入笔杆倾角、含墨量和时间状态。用未参与拟合的试笔评估预测误差。
3. **机器人执行**：标定相机到纸面、纸面到机器人坐标系，转换归一化路径为毫米轨迹，加入抬落笔、工作空间、速度/加速度和接触力限制。先写简单笔画和单字。
4. **真实视觉反馈**：先逐笔拍照纠偏，再实现笔画内部反馈；比较固定、开环、闭环的实际墨迹、重复性、书写时间和失败率。
5. **风格与大模型**：在真实执行稳定后，引入风格参考图或文本指令，并建立风格相似性人工评价。把高层风格生成与底层安全控制分别验证。

## 8. 相关研究与阅读顺序

1. **数据格式**：[Make Me a Hanzi 官方 README](https://github.com/skishore/makemeahanzi/blob/master/README.md)。重点看 `graphics.txt` 的 `strokes`、`medians`、坐标系与许可，避免把中线当成真实机器人轨迹。
2. **在线轨迹与离线图像**：Park 等，[*Bridging Online and Offline Handwriting via Differentiable Physical Rendering*](https://arxiv.org/abs/2608.03198)，2026。重点看轨迹生成、笔刷参数观察器、可微渲染和真实物理量标定的边界。本地 PDF 与[阅读导引](OnOff_阅读导引.md)已保存。论文方案比本项目当前的回归和合成笔刷复杂，不能写成本项目已复现。
3. **书法图像到机器人动作**：Luo 等，[*CalliRewrite: Recovering Handwriting Behaviors from Calligraphy Images without Supervision*](https://arxiv.org/abs/2405.15776)，ICRA 2024。重点看图像到笔画序列、模拟笔刷优化、真实机器人验证；用于说明下一阶段如何从固定数据集目标扩展到任意书法图像。

## 9. 复现与材料索引

在项目目录执行（Python 3.10+）：

```powershell
python -m pip install -e .
calligraphy-sim --char 永 --profile standard --size 256 --out outputs/ppt_demo
calligraphy-sim-suite --size 192 --out outputs/closed_loop_sim
calligraphy-sim-suite --chars 中天春秋月 --size 192 --out outputs/heldout_sim
python -m unittest discover -s tests -v
```

核心代码在 `src/calligrapher/`：`sim_data.py`（数据）、`sim_brush.py`（环境）、`sim_planner.py`（标定与规划）、`sim_control.py`（反馈与评价）、`sim_cli.py`（单字导出）、`sim_suite.py`（批量实验），`geometry.py` 提供轨迹几何处理。运行时需要 NumPy 与 Pillow，普通笔记本 CPU 即可；真实机械臂阶段另需机器人控制与相机软件栈。
